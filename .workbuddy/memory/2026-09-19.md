## 启动项目（BRMES）
- 多模块 .NET 10 方案 + Vue3/Vite 前端，双服务本地跑通。

## UI 精调：统一深色主题（经确认走"统一深色主题"方向）
- **根因**：背景是深色 `#0b1220`，但从未引入 Element Plus 暗色主题、也没覆盖任何 `--el-*` 变量 →
  el-card / el-table / el-input / el-dialog 全是默认**白底浅色**，只有侧边栏手工刷成深色，属于"半套深色皮"。
- **改动**：`main.ts` 在 `element-plus/dist/index.css` 之后引入 `element-plus/theme-chalk/dark/css-vars.css`，
  并 `document.documentElement.classList.add("dark")`；`styles.css` 用 `html.dark {}` 把官方变量覆盖到项目色板。
- **关键坑**：主色 `--el-color-primary` 改为 `#3d8bfd` 后，**必须同时重写 `light-3/5/7/8/9` 和 `dark-2`**，
  否则 hover / active 态会跳回 Element Plus 默认蓝 `#409eff` 系。
- 输入框用 `--el-fill-color-blank: #0e1626`（比卡片 `#121a2b` 深，形成凹陷感）；卡片用组件级 `--el-card-bg-color`
  单独指定，避免与 fill-color-blank 同色；表格表头 `#16203a` 与数据行做微差，防止整片同色糊在一起。
- 顺带：`h1~h4 { margin: 0 }` 统一垂直节奏（页标题 h2 外边距、KPI h1 默认 2em 字号都很松散）；
  Dashboard KPI 卡加 `.kpi-label/.kpi-value`（`tabular-nums` 防 4s 轮询时数字宽度跳动）；
  可点击卡片补悬停反馈（原先只有 `cursor:pointer`）。
- 验证：`vue-tsc --noEmit` 0 错；`/src/main.ts` 已解析出 dark css-vars，`/src/styles.css` 返回覆盖后的变量。
- **用户偏好记录**：视觉类改动倾向先确认方向再落代码（本次用 AskUserQuestion 给了 3 个方向让其选）。

## 易用性第二批：列表页统一样式/反馈（8 个页面）
- 新增 `src/utils/useLoad.ts`：`useLoad()` 返回 `{ loading, error, run }`，统一「首屏 loading + 就地错误提示条」。
  loading 只首屏为 true，轮询刷新不闪 mask（Dashboard/BatchList/EquipmentList 都是 4s 轮询）。
- **两个类型坑（已修，勿重蹈）**：
  1. `http.get<T>()` 返回 `Promise<AxiosResponse<T>>` 而非 `Promise<T>` → `run` 签名必须按 `Promise<{data:T}>` 解包，
     否则 `items.value = d` 会被塞进整个 Response。
  2. 回调返回类型要写 `unknown`，不能写 `void | Promise<void>`——目标返回值是 `void` 时 TS 才允许任意返回，
     一旦是联合类型，简洁写法 `(d) => (items.value = d)` 会因返回数组报 TS2322。
- 新增 `src/utils/format.ts`：`formatDateTime/formatDate/formatNumber`。
  修了真实缺陷：AuditLog 的「时间」列直接渲染原始 ISO 串，而 AlarmList 却用 toLocaleString，同一信息两种长相。
- 已套用统一模式的页面：AlarmList、AuditLog、LotList、LotGenealogy、RecipeList、Approvals、EquipmentList、UserAdmin。
  各页面同时补了：写入类操作的 `:loading` 防重复提交（原先 LotList 登记、UserAdmin 保存、装备保存、拆分等都没有）。
- LotGenealogy 根节曾是 `v-if="tree"`，**取数失败整页空白无任何提示** → 补 error/skeleton 分支。
- 发现并收敛了多处「重复且口径不一致」的标签：RecipeList 内联 `Author:"提交"` vs labels.ts 的"工艺工程师提交"；
  EquipmentList 协议列裸 SiemensS7 而同页下拉写 "Siemens S7"；UserAdmin 角色列和下拉都裸英文 Admin/Operator。
  新加了 `approvalLevelLabel/approvalDecisionLabel/auditEntityLabel` 并复用 `userRoleLabel/protocolLabel`。
- 全局新增 `.clickable-rows`：整行可点的表格此前光标不变、无指针反馈（写在全局而非 scoped，scoped 穿透不到 el-table 内部 tr）。
- 验证：`vue-tsc --noEmit` 0 错；改动模块经 dev server 均返回 200。
- 注意：Vite 只在有浏览器 client 连接时才在日志里打 hmr update，未连接时日志为空不代表没生效，直接 curl 模块看 200 即可。
- 未处理（刻意留待后续）：BatchMonitor / BatchRecord / RecipeDesigner 三个详情重页。

## tooltip 术语系统（从零建立）
- **先前状态**：全应用零 `el-tooltip`。解释文案散落在 el-alert 横幅、placeholder、原生 title 属性里，
  术语本身没有任何可发现入口（操作员看到「等待 PLC 应答」无法知道含义）。
- 新增 `src/utils/glossary.ts`：领域术语字典 + `tipOf(key)`。22 条术语，覆盖控制配方快照/完整性哈希/
  四步握手七个阶段/PLC_Ready/Trigger_Write/禁止盲写/设备占用/ISA-88 层级/电子签名/漂移等。
- 新增 `src/components/HelpTip.vue`：`el-tooltip` 之上包一层，**字典缺项自动降级为普通文本**（不会出现空提示气泡）。
- **关键设计约定**：glossary 的 key 直接用 `labels.ts` 输出的中文，且同一术语要同时收 "定义" 一句 + 可选 "补充"，
  由 `tipOf` 用 `\n\n` 拼起来。因此 table 里可以直接
  `<HelpTip :term="handshakePhaseLabel(row.handshakePhase)">{{ handshakePhaseLabel(row.handshakePhase) }}</HelpTip>`
  ——当前阶段值本身就是 key，未收录的阶段（如「等待人工确认」）自动无提示，天然向后兼容。
- CSS 坑：el-tooltip 的气泡被渲染到 body 下，**样式必须写在全局**（`.help-tip-pop`，含 `white-space: pre-line` 让 \n\n 生效），
  scoped 无效——和 `.clickable-rows` 同理。
- 已接入：Dashboard（占用/握手两表头 + 阶段值）、BatchList（表头 + 阶段值）、EquipmentList（占用表头）、Approvals（电子签名链）。
- 未接入（术语同样密集）：RecipeDesigner 的单元规程/操作标签、BatchMonitor 握手卡片、EquipmentList 点表变量名。
- 验证：`vue-tsc --noEmit` 0 错；所有涉及模块经 dev server 返回 200。
