### 踩坑

- **vite 只监听 IPv6**：`curl http://127.0.0.1:5173` 连接被拒，`localhost` / `[::1]` 都 200。playwright 脚本 BASE 必须用 `localhost`。
- Bash 工具 `run_in_background=true` **不要再加 shell `&`**——外层立即退出、子进程被回收（日志空、task 秒 completed）。直接 `run_in_background` 即可。
- `dotnet run ... | tail -40` 的管道会缓冲，后台任务看不到启动日志；用 `/health` 探测代替读日志。

## 第二轮：自动巡检找出遗漏项（同轮续做）

第一轮靠肉眼逐页看，漏了两页。第二轮改用**自动巡检脚本**（遍历 9 页 × 2 主题，自动量化折行/横向溢出/对比度），一次找出全部残余问题——这个方法比看图可靠，以后改 UI 先跑它。

查出并修复 3 处：

1. **主配方设计页折行 37 处**：编码列 `width=140` 无 tooltip。14px 字体实测编码最长 136px（比批次表的 12px 大），减 padding 24 只剩 116px → 折行。改 `176` + tooltip。
2. **批次执行页状态列折行 2 处**：`已创建`(52px) + `待检终样`(64px) 并排需 120px，列宽 `96` 放不下 → `flex-wrap` 折两行、格高 48px（全表仅这两行高别人一倍）。改列宽 `144`（120+padding24）让两标签并排，行高恢复一致。
3. **总览页空闲行低对比度 4.42:1（6 处）**——**这是第一轮斑马纹改动引入的回归**：偶数行底色从 `--sunken` 换成 `--table-zebra` 变亮，`--idle` 对比度从 4.60 降到 4.10；且 `--panel` 上本来就只有 4.42（既有问题，注释误写「≥3:1」但实际当 14px 正文用需 4.5）。
   改：深 `--idle #6d81a6 → #7b8fb5`（三底色 5.33/4.95/5.19）、浅 `#64748b → #5c6b82`（5.41/4.98/4.72）。

**教训**：改色板层次（尤其「让某底色变亮」）后要重扫全站对比度——斑马纹提亮会连累压在该底色上的所有次要文字。`--idle` 语义注释与实际用法（14px 正文）不符，是这次漏判的诱因。

残余（判定为合理、不修）：配方页「名称」列 2 处长中文（`上位机等待剩余时长示范`）在自动列里换行，属正常。

验证：vue-tsc 干净 + vitest 69/69 + 巡检两主题全 `ok`（wrap/overX/lowContrast 均为 0）。

## 第三轮：扩大巡检维度（结论：无改动）

第三轮换扩展维度巡检（控件触达尺寸 / 字号阶梯 / 空态兜底 / 元素间距 / 列宽分配 / AAA 对比度），**结论是硬性缺陷已在前两轮清完，本轮 0 改动**。这一轮的价值主要是**避免误改**——多个初看像问题的项，实测后判定为合理设计：

| 初看像问题 | 实测 | 判定 |
|---|---|---|
| 帮助中心 4 处 10px 字号 | 对比度 6.57~6.68:1（远超 4.5） | 刻意的「眉标」设计（大写+字距 .08em+字重 650），不改 |
| 设备页操作列按钮「挤在一起」 | 实测间距 12px（EP 默认），是截图缩放错觉 | 不改 |
| 表格内 link 按钮高 20px | 用户页 3 个 + 设备页 3 个，口径一致 | 一致即非缺陷，不改 |
| 总览两表宽度差 242px（1044 vs 1286） | `.dash-main` 是 `minmax(200,230px) 1fr` 两栏栅格，注释写明「宽度让给设备占用表」 | 刻意布局，不改 |
| 「执行态势」卡片空态下方大片空白 | grid 行高由较高者定，有事件时会填满 `max-height:236px` | 数据自然状态，不改 |
| 主色文字 4.85:1 | 是 `--accent` 固有对比度，要提必须改主色 | 收益<风险，不改 |
| 间距硬编码 | `grep` 全站无 `margin/padding` 非令牌残留 | 早已收拾干净 |

巡检脚本报 `caret-wrapper`（24×14）是 EP 排序箭头**内部结构**误报——它的父级 th 才是可点区域，检测时需过滤。

方法沉淀：巡检要**先量化再判断**，且要能识别「误报」（内部结构、截图错觉）与「刻意设计」。三轮下来，`--space-*` 令牌化 + 前两轮修复已让全站 UI 达到无硬性缺陷的状态。

## 第四轮：易用性改进（视角切换）

前四轮都是「视觉/一致性」标尺，这轮换成**易用性**标尺：错误预防 / 反馈及时性 / 可发现性 / 效率。

**方法**：不做静态截图，改做**角色差分实测**——用 5 个角色（管理员/工艺工程师/工艺主管/质量工程师/车间操作员）各自独立 context 登录，遍历 5 个页面，对比「能看到什么按钮、有什么提示」。这一步直接暴露了权限相关的易用性缺口。

### 排查结论（先排除误报）

- **危险操作确认**：8 个文件有 ElMessageBox.confirm，覆盖到位。`dropStep` / `removeEdgeAt` / `removeLastParam` 无确认是**正确的**——都是草稿态编辑（`working.value`/`draft.steps`），点保存才落库；`removeStep` 有详细确认框（注释明写「要说清丢什么」）。
- **空态文案**：区分「搜索无结果」vs「真的没数据」，且有空库引导（设备页/批次页注释「比暂无四个字有用得多」）——做得好。
- **管理员看不到创建批次按钮**：**不是缺陷**。`docs/auth-matrix.md` 第 17-18 行明确「名单是闭集…管理员不碰产线（不能启停、跳步、放行）」，是刻意的职责分离。
- **路由级无权限**已有提示（router/index.ts:113 跳回总览并说明原因，报警/设备/审批页都有黄条）。

### 真实缺口与修复（1 处）

**页面内权限差异是静默的**：管理员/质量工程师进 `/batches` → 零按钮、零提示，副标题只说功能不说权限，页面看起来「像坏了」。而主管/操作员有「从已批准配方创建」。

改：`BatchList.vue` 页头右侧，无创建权限时用一句 `--muted` 12px 说明代替按钮——「本页仅供查看；创建批次需要主管或操作员账号。」（说清「为什么没有」+「该找谁」）。抽 `canCreate` computed 与按钮同口径。

**只改批次页、不动报警页**是刻意的：管理员在报警页能看到完整数据（12 条、级别标签、红条），页面不显得空，加提示反而是噪声。判断依据是**看渲染实况**，不是照搬同一模式。

验证：5 角色差分实测（管理员见说明无按钮 / 主管见按钮无说明）；vitest 69/69（含 i18n 覆盖率棘轮——新文案漏进 en.ts 时被准确拦下，按约定补齐）；vue-tsc 干净。
